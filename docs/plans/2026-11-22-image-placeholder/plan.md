## 背景・目的

日記の画像は、保存済みの寸法を使って読み込み前から場所を空けて組むので、読み込みで文章が動くことはなくなった。一方で、画像が届くまでの間、空けた場所には用紙の地の色しか見えず、届いた瞬間に画像が突然現れる。読み込みに失敗したときは、何もない空白が残るだけで、写真があるはずだったことが伝わらない。

空けた場所に淡い色の台紙を置いて「ここに写真が入る」ことを見せ、届いた画像はふわっと現す。失敗したときは台紙を残し、読み込めなかったことが分かる小さな印を出す。

## スコープ

- 寸法が分からない画像（寸法が NULL で、読み込みも終わっていない）の扱い。今までどおり、読み込みが終わるまで場所を取らず、台紙も出さない

- DB、API、アップロード、一括パッチ
- ぼかした縮小版（blur-up）の表示

## 方針

### 画像の状態

FlowText は、いまの `imageSrc` について次の 3 つの状態のどれかを render 中に導出する。状態（待ち / 表示 / 失敗）は props と state から render 中に導出し、state を同期するための `useEffect` は足さない。ペイント前に DOM の状態を確かめる必要がある場合に限り、`useLayoutEffect` を使ってよい（このリポジトリの Effect の指針に沿う）。

| 状態 | 条件 | 表示 |
|---|---|---|
| 待ち | いまの src の読み込みが終わっておらず、失敗もしていない | 台紙だけ。img は透明 |
| 表示 | いまの src の読み込みが終わった | 画像。台紙は消える |
| 失敗 | いまの src の読み込みが失敗した | 台紙と小さな印。img は見せない |

- 読み込み済みは、既存の `loadedSize`（測った src つき）が、いまの `imageSrc` と一致することで判定する。読み込み済みの判定は、いまの `imageSrc` と同じ `src` が設定された要素について行う（既存の `loadedSize` は測った src を一緒に持っているので、この条件を保つ）。
- 失敗は、失敗した src を state に持ち、いまの `imageSrc` と一致することで判定する。src が変われば、前の画像の失敗は使わない。
- 前提（既存の事実）: 公開ページでは FlowText が SSR され、ハイドレーションで画像の要素が新しく作り直される。また `<img>` の属性は書いた順に設定され、いまのコードは `ref` が `src` より先にあるので、ref callback が呼ばれた時点では新しい img に `src` がまだ無いことがある。`src` の無い img は `complete` が true で `naturalWidth` が 0 になる。
- したがって、ref callback の時点の `complete` と `naturalWidth` だけで失敗と決めてはならない。失敗として記録してよいのは、その img 要素に、いまの `imageSrc` と同じ `src` が設定されていて、その要素で読み込みが失敗したとき（その要素の `error` イベント、または `src` が設定済みの要素で `complete` が true かつ `naturalWidth` が 0）だけ。
- 読み込み中の正常な画像に、失敗の印が出てはならない。
- ハイドレーション後の表示は、作り直された img 要素での読み込みの成否で決まる。作り直された要素でも失敗すれば「失敗」の表示（作り直された img が同じ src を読み直して失敗し、その `error` で記録される、という経路でよい）、成功すれば画像を表示する。SSR の HTML にあった img だけが失敗し、作り直された img が読み込めた場合は、画像を表示する（失敗の表示にしない）。
- 属性の順序を変える、ペイント前に DOM を確かめる、などの実現方法は実装担当が決めてよい。
- 状態の導出は純粋関数にして `app/lib/` に置き、ユニットテストを書く（FlowText のテストは SSR だけで、DOM のイベントは試せないため）。

### 台紙

- 台紙は、枠（外接矩形の button）の中に絶対配置で置く要素で、画像と同じ表示サイズ（`imageSize`）、同じ角丸（12px）、同じ回転にする。枠の大きさ・位置・回り込みの計算には一切関わらない（レイアウトに影響させない）。
- 台紙が出るのは、枠の大きさが決まっていて（`frameSize` がある）、状態が「待ち」か「失敗」のとき。
- 色は用紙専用のトークンで決める。`.paper, .paper-frame` に台紙用のトークン（例: `--paper-mat`）を足し、ライトでは黒の、ダークでは白の、ごく薄い半透明にする（既存の `--paper-line` と同じ考え方で、濃さは 0.06〜0.12 の範囲で実装担当が画面を見て決める）。利用者が選んだ用紙の色の上で、どの色でも「少しだけ色が違う面」に見えること。
- 台紙の面そのものは飾りで、支援技術には読ませない。ただし、失敗の印に付ける名前「写真を読み込めませんでした」は支援技術に届かなければならない。印を `aria-hidden` の付いた要素の内側に置いて名前を隠してしまわないこと。要素の入れ子や属性の付け方は実装担当が決めてよい。

### ふわっとした表示

- 「待ち」から「表示」に変わるとき、画像と台紙の `opacity` の CSS transition で、画像の不透明度を 0 から 1 へ、台紙を 1 から 0 へ、同じ時間で同時に変える（200〜320ms の範囲、ease-out 系。時間と曲線の細部は実装担当が画面を見て決める）。
- 台紙は画像の後ろに残さない。透過のある PNG / WebP で、台紙が透けて見えないようにするため。
- フェードするのは、台紙が見えていたときだけ。次の場合はフェードせず、すぐに表示する。
  - ハイドレーションの時点で画像が既に読み込み済みだった（キャッシュ済みなど）
  - 既に画像を表示している枠で、src が別の画像に変わった（編集画面で、プレビューから保存済みの URL に切り替わるときや、画像を選び直したとき）。このときは台紙も出さず、今までどおりブラウザが前の画像を新しい画像に置き換える。編集中に画像が一瞬消えるちらつきを作らないため。
- つまり「待ち」の表示（台紙と透明な img）になるのは、その枠でまだ一度も画像を表示していないときだけ。一度表示したあとの src の変更では、失敗したときだけ「失敗」の表示になる。
- 「一度表示した」という履歴は、画像が途切れずに切り替わる間だけ続く。
- 「その枠で写真を表示済み」とは、画像が無い状態（`imageSrc` が null。最初に枠ができる前も含む）から途切れずに続いている間に、その枠でどれかの画像の読み込みが終わって表示されたことがある、という意味。
- 表示済みの枠では、`imageSrc` が別の画像に変わっても、台紙もフェードも出さない。変わった先の画像の読み込みがまだ終わっていなくても、途中に読み込みが終わらないまま通り過ぎた画像があっても同じ。ブラウザが、表示中の画像を新しい画像に置き換えるのに任せる。
  - 例: 画像 A の読み込みが終わって「表示」になっている枠で、`imageSrc` が null を挟まずに B に変わったときは、台紙もフェードも出さず、ブラウザが A を B に置き換えるのに任せる。
- 前提（既存の事実）: 保存済みの写真を表示中に画像を選び直すと、`imageSrc` は「保存済みの写真（表示済み）→ 新しいプレビュー（読み込みが終わる前に通り過ぎることがある）→ 新しい保存済みの URL」と変わる。アップロードはプレビューの読み込みを待たずに進むためである。この間ずっと表示済みの枠として扱い、表示中の写真が台紙に置き換わって消えることがないようにする。
- 前提（既存の事実）: 編集画面で画像の無い日記に初めて画像を選ぶと、プレビューの読み込みが終わるのを待たずにアップロードが進むので、プレビュー（A）を一度も表示しないまま、保存済みの URL（B）に切り替わることがある。
- まだ何も表示していない枠（初めて画像を選んだときで、プレビューが表示される前に保存済みの URL へ切り替わった場合を含む）では、「待ち」を続ける。
  - 例: A がまだ「待ち」のまま（一度も表示していない）B に変わったときは、B でも「待ち」を続ける（台紙を出したままにし、B が届いたらフェードで現す）。
- 画像を削除して `imageSrc` が null になったら、履歴はそこで終わる。そのあと別の画像を追加したときは、新しい枠として「待ち」から始める（台紙が出てよく、届いたらフェードする）。
- この区別を、状態を導出する純粋関数のユニットテストで確かめる。
- 編集画面で、画像の無い日記に初めて画像を選んだときは、その枠でまだ一度も画像を表示していないので、公開ページと同じ「待ち」の扱いになる（枠の大きさが決まっていれば台紙が出て、プレビューの読み込みが終わるとフェードで現れる。プレビューはすぐ読み込まれるので、台紙が見えるのは一瞬か、見えないこともある）。これは意図どおりで、防がない。
- `prefers-reduced-motion: reduce` のときは、フェードせずに切り替える。メディアクエリが要るので、フェードは `global.css` のクラスで書く（インラインの style ではなく）。
- テーマの切り替え中（`.theme-transition` が付いている短い間）は、`app/styles/global.css` の既存の指定が全要素の `transition-property` を `!important` で上書きする。この間に届いた画像は、フェードせずに切り替わってよい。この指定は変えず、打ち消す指定も足さない。

### 失敗したとき

- 台紙を残し、中央に小さな印（写真を読み込めなかったことを表すアイコン。インラインの SVG、色は `--paper-muted`、大きさは 24〜32px を目安に、台紙が小さいときははみ出さない）を出す。
- 印には、支援技術向けの名前「写真を読み込めませんでした」を付ける。目に見える文字は出さない（枠が小さいことがあり、縦書きの紙面の中で文字が浮くため）。
- 失敗した img は見せない（ブラウザの壊れた画像のアイコンと alt の文字が台紙に重ならないようにする）。
  - 前提（既存の事実）: 横スクロールの枠（`app/islands/diary-scroll-frame.tsx` の測定）は、本文の列・日付・`img` の左端から表示する幅を決めている。台紙や button は測定の対象ではない。
  - そのため、失敗した img は DOM から外さず、`display: none` にもしない。描画だけを隠して（不透明度を 0 にする、`visibility: hidden` にする、など）、要素の矩形は表示時と同じ位置・大きさのまま保つ。
  - 狭い画面で、本文より左に失敗した画像の枠があるとき、横スクロールで台紙と印まで届くこと。
  - `diary-scroll-frame.tsx` の測定の処理は変えない。
- 「待ち」の間の透明な img も同じく、矩形を保つ（不透明度だけで隠す）。
- 公開ページ（`draggable` でないとき）では、失敗した画像の枠は押せない状態にする。押しても画像ビューワーを開かず、カーソルは押せることを示す形（pointer）にせず、キーボードのフォーカスも受けない。読み込めた画像の枠は今までどおり押せて、ビューワーが開く。押せない状態にする方法（`disabled` を使う、button 以外の要素にする、など）は実装担当が決めてよい。印の名前が支援技術に届くことは保つ。
- 公開ページでは、待ちの間も今までどおり枠を押せて、画像ビューワーが開く。ビューワーが開いたあとに画像の読み込みが失敗したときは、ビューワーを閉じる（「失敗」の状態ではビューワーを表示しない）。最終的に、ビューワーが閉じた状態で台紙と印が見える。
- 編集画面（`draggable`）では、失敗していても今までどおり枠をつかんで動かせる。
- 文章の位置は変えない（場所は空けたまま）。

### 変えないこと

- 枠の位置・大きさ、文章の回り込み、日付の位置。読み込みの前後、失敗の前後で、文章の各列の位置は変わらない。
- 寸法が渡されない画像のふるまい（読み込み後に場所を取る）。この場合、画像は読み込みが終わった時点で初めて枠が決まるので、台紙は出ない。表示はフェードなしでよい。
- 保存済みの寸法と、読み込んだ画像の実寸の縦横比が違うときは、読み込み後に実寸で組み直される（既存の仕様。`docs/architecture/image-upload.md` に記載がある）。寸法が無いときは、読み込み後に初めて場所を取る。今回はどちらも変えない。文章の位置が読み込みの前後で変わらないのは、保存済みの寸法が実寸と一致しているとき。
- SSR の出力で配置を計算しないこと（枠は今までどおり、クライアントで幅を測るまで見せない）。
- CSP、依存パッケージ。

## 完了条件・受け入れ基準

1. 寸法が保存されている画像を、読み込みを遅らせて公開ページで開くと、画像が届くまでの間、画像と同じ位置・大きさ・角丸・傾きの淡い色の台紙が見える。
2. 画像が届くと、画像の不透明度が 0 から 1 へ、台紙の不透明度が 1 から 0 へ、200〜320ms の transition で変わる（途中では、どちらも 0 と 1 の間の値を取る）。表示が終わったあと、台紙は見えない（透過のある画像でも、後ろに台紙の色が見えない）。テーマの切り替え中に届いた場合は、フェードせずに切り替わってよい。
3. 保存済みの寸法が画像の実寸と一致しているとき、読み込みの前後で、文章の各列と日付の位置・大きさが変わらない。
4. 画像がブラウザにキャッシュ済みで、ページを開いた時点ですぐ読み込みが終わる場合は、台紙もフェードも見せずに画像を表示する（枠が最初に見える時点で、画像が不透明度 1、台紙が見えない状態になっている）。
5. `prefers-reduced-motion: reduce` の環境では、transition なしで画像へ切り替わる（途中の値を取らない）。
6. 画像の読み込みが失敗すると、台紙が残り、中央に印が出る。印には「写真を読み込めませんでした」という名前が付いている。ブラウザの壊れた画像のアイコンや alt の文字は見えない。文章の位置は、失敗の前後で変わらない。
7. SSR の HTML にあった img の読み込みがハイドレーションより前に失敗し、ハイドレーションで作り直された img の読み込みも失敗する場合、6 と同じ表示になる。作り直された img が読み込めた場合は、画像を表示する。読み込み中の正常な画像（ハイドレーションの時点でまだ届いていない画像）には、失敗の印が出ない。
8. 公開ページで、失敗した画像の枠は押せない（押しても画像ビューワーが開かず、カーソルが pointer にならず、Tab キーでフォーカスが止まらない）。待ちの間に枠を押してビューワーを開いたあとで読み込みが失敗した場合は、ビューワーが閉じ、台紙と印が見える。読み込めた画像は今までどおり押せて、画像ビューワーが開く。
9. 編集画面のプレビューで、画像を選んでアップロードが終わるまでと終わったあと（プレビューから保存済みの URL への切り替わり）、および画像を選び直したとき、表示中の画像が台紙に置き換わって消えることがない。
10. 編集画面で、失敗の表示になった枠も今までどおりドラッグで動かせる。
11. 寸法が無い画像（寸法が NULL）は今までどおり、読み込みが終わってから場所を取り、台紙は出ない。
12. ライトとダークの両方、および用紙の色を変えても、台紙が用紙の地と見分けられ、印が読める。
13. 画像の状態を導出する純粋関数に、次のユニットテストがある: 読み込み前は「待ち」、いまの src の読み込み後は「表示」、いまの src の失敗は「失敗」、前の src の失敗や読み込みは、いまの src の状態に使われない、A を表示済みの枠で src が B に変わったときは、台紙を出さない、A が待ちのまま src が B に変わったときは、B でも待ちを続ける（台紙を出す）、表示済みの枠で、読み込みが終わらないまま通り過ぎた画像を挟んで src が変わっても（表示済みの A → 未読込の B → C）、台紙を出さない、ハイドレーション時に読み込み済みならフェードしない、画像を削除したあと（src が null を挟んだあと）に追加した画像は、新しい枠として「待ち」から始まる、いまの src が設定されていない要素の状態（src の無い img の complete / naturalWidth）を、失敗として扱わない（純粋関数の入力として表せる範囲で）。
14. 状態を同期するための `useEffect` を新しく足していない（状態は render 中に導出する。ペイント前の DOM の確認に `useLayoutEffect` を使うのはよい）。
15. `pnpm run typecheck`、`pnpm run lint`、`pnpm run test`、`pnpm run build` がすべて成功する。
16. 依存パッケージ、CSP、DB、API に変更がない。
17. `docs/architecture/image-upload.md` に、読み込み中・読み込み後・失敗時の表示が書かれている。
18. CI（workflow「CI」の job `ci`: lint・typecheck・test）が、PR を作る場合はその HEAD で成功する。

## 未確定事項・リスクと判断の委ね方

| 項目 | 内容 | 実装時の扱い |
|---|---|---|
| 台紙の濃さ、フェードの時間、印の形と大きさ | 上の方針の範囲内で、見た目を見て決める | 実装担当が判断してよい。範囲を外れる必要があれば理由を報告する |
| 純粋関数の置き場所と名前、state の持ち方 | `app/lib/image-dimensions.ts` に足すか、新しいファイルにするか | 実装担当が判断してよい |
| 「一度表示したか」の持ち方 | 既存の `loadedSize` が null かどうかで足りるか、別の state が要るか | 実装担当が判断してよい。受け入れ基準 4・9 を満たすこと |
| 台紙と印の要素の構造 | 台紙の面は飾りとして隠し、印の名前は支援技術に届かせる。入れ子と属性の付け方 | 実装担当が判断してよい。受け入れ基準 6 を満たすこと |
| 失敗後の再試行 | 自動の再読み込みはしない | 対象外。足さない |
| 画像の配置の計算や、寸法が無い画像の扱いを変える必要が出た | スコープ外 | 止まって報告する |

## 公開経路

作業ブランチ `plan/2026-11-22-image-placeholder` に commit する。検収の合格後、采配役が push し、main への PR を作る（承認済み）。main は PR 経由でだけ変更でき、必須チェックは CI の `ci`。マージとデプロイ（`pnpm run deploy`、手動）は利用者が行う。自動デプロイは無い。マイグレーションは無い。
